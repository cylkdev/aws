# AwsSdk Codegen, Phases 0–2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Extract the duplicated runtime out of the nine service modules, build a
code generator driven by `AwsSdk.Codegen` structs plus vendored AWS models, and
prove it end-to-end by replacing the hand-written `AwsSdk.AutoScaling` with a
generated one that passes characterization tests.

**Architecture:** Two inputs per service — a hand-owned curation spec at
`priv/specs/<service>.exs` and a vendored AWS SDK Go v2 model at
`models/<service>.json`. `mix aws_sdk.gen` reads both and writes ordinary Elixir
source to `lib/aws_sdk/<service>.ex` and `lib/aws_sdk/<service>/sandbox.ex`. No
macros, no `use`, no runtime interpretation: generated code calls plain shared
modules and reads like the hand-written code it replaces.

**Tech Stack:** Elixir, EEx (generation only), SweetXml, `:json`, Recase,
ExUtils.Serializer, SandboxRegistry (optional dep, `:dev`/`:test`).

**Spec:** `docs/superpowers/specs/2026-08-07-codegen-driven-sdk-design.md`

**Scope:** Phases 0–2 of the spec. Phase 3 (rolling the remaining eight services
onto the generator) and Phase 4 (S3, the request sub-language, and generated
presign entry points) are follow-on plans. This plan ends with exactly one
generated service in the tree, which is what makes the approach reviewable before
it is applied 200 operations wide.

## Global Constraints

- `mix compile` treats warnings as errors in non-test envs. Every task must
  leave the tree compiling clean.
- `mix format` must pass. Generated output must be format-clean as emitted, not
  reformatted afterwards.
- `SandboxRegistry` is an optional dep compiled only in `:dev`/`:test`. Nothing
  outside an `if Code.ensure_loaded?(SandboxRegistry) do` block may reference
  `AwsSdk.Sandbox` or any `AwsSdk.*.Sandbox` module unconditionally.
- Response fidelity rules in `CLAUDE.md` are non-negotiable and are the
  specification for the parser compiler: nesting preserved, names preserved,
  lists preserved, nothing dropped, envelope dropped.
- Every AWS-required input stays a positional argument enforced by a guard on the
  function head. Never a runtime check on the keyword list.
- `models/` is excluded from the hex package (`mix.exs` `:files`).
- Generated files carry the header `# Generated by mix aws_sdk.gen — do not edit`
  and are committed to git.

The facade is character-for-character what you write today except `sandbox?/1`
is generated rather than typed, `flatten_query/1` is spelled
`AwsSdk.Query.encode/2` at the call site, and `build_operation/3` is
`AwsSdk.Protocol.Query.build/4`. **This is deliberate.** The generator is not an
opportunity to invent a nicer shape; it emits the shape you already chose.

The parser is emitted from the model with the same structure as today's:

```elixir
  defp parse_describe_instance_refreshes(body) do
    result =
      xpath(body, ~x"//DescribeInstanceRefreshesResult"e,
        instance_refreshes: [
          ~x"./InstanceRefreshes/member"l,
          instance_refresh_id: ~x"./InstanceRefreshId/text()"os,
          auto_scaling_group_name: ~x"./AutoScalingGroupName/text()"os,
          status: ~x"./Status/text()"os,
          status_reason: ~x"./StatusReason/text()"os,
          start_time: ~x"./StartTime/text()"os,
          end_time: ~x"./EndTime/text()"os,
          percentage_complete: ~x"./PercentageComplete/text()"oi,
          instances_to_update: ~x"./InstancesToUpdate/text()"oi,
          preferences: [
            ~x"./Preferences"o,
            auto_rollback: ~x"./AutoRollback/text()"os,
            ...
          ]
        ],
        next_token: ~x"./NextToken/text()"os
      )

    %{
      instance_refreshes: Enum.map(result.instance_refreshes, &coerce_instance_refresh/1),
      next_token: AwsSdk.Params.nilify(result.next_token)
    }

```

SweetXml has no boolean or timestamp modifier, so coercion happens in a generated
`coerce_*/1` pass over the extracted map. That pass is what turns `"false"` into
`false` and `"2026-01-01T00:00:00Z"` into a `DateTime`, and it is generated from
the same `%AwsSdk.Codegen.Field{}` list as the selectors.

### After — generated `lib/aws_sdk/auto_scaling/sandbox.ex`

```elixir
    def describe_instance_refreshes_response(auto_scaling_group_name, opts) do
      binding = [auto_scaling_group_name: auto_scaling_group_name, opts: opts]

      Sandbox.apply(
        @registry,
        __MODULE__,
        :describe_instance_refreshes,
        auto_scaling_group_name,
        binding
      )
    end

    def set_describe_instance_refreshes_responses(entries) do
      Sandbox.register(@registry, __MODULE__, :describe_instance_refreshes, entries)

```

Note the parameter is now named `auto_scaling_group_name`, not `asg`. Today the
facade calls it `auto_scaling_group_name` and the sandbox calls it `asg` — two
names for one value, and the mismatch surfaces in `AwsSdk.Sandbox`'s error
messages, which print `fn asg -> ... end` as the suggested stub shape for a
function whose argument the docs call `auto_scaling_group_name`. Generating both
from `args` makes that class of drift impossible.

### Behaviour deltas this operation will show

These are the Phase-1 characterization assertions that will change, each one
either a fix or a regression to triage:

| Key | Today | Generated | Why |
|---|---|---|---|
| `end_time` | `""` when absent | `nil` | `~x"..."s` on a missing node yields `""`; the member is optional in the model |
| `status_reason` | `""` when absent | `nil` | same |
| `start_time` | `"2026-01-01T00:00:00Z"` | `~U[2026-01-01 00:00:00Z]` | model types it `timestamp`; `CLAUDE.md` requires the coercion |
| `preferences.skip_matching` | `"false"` | `false` | model types it `boolean` |
| `preferences.auto_rollback` | `"false"` | `false` | model types it `boolean` |
| members absent from the parser | not returned | returned | fidelity rule 4 — enumerated by Task 15 Step 3 |

`start_time` and the two booleans are **breaking changes for callers that
pattern-match the binary.** They are correct per `CLAUDE.md`, they are the reason
this project is worth doing, and they must appear in the changelog.

```elixir
# lib/aws_sdk/params.ex
defmodule AwsSdk.Params do
  @moduledoc """
  Value-level helpers shared by every service's request and response handling.

  Both functions exist because AWS distinguishes an absent value from an empty
  one and SweetXml does not: `maybe_put/3` keeps an absent input out of the
  request entirely, and `nilify/1` maps the `""` that an optional-string
  selector yields back to `nil`.
  """

  @doc """
  Puts `value` under `key` unless it is `nil`.

  `false` and `[]` are values, not absences, and are kept.

      iex> AwsSdk.Params.maybe_put(%{}, "Enabled", false)
      %{"Enabled" => false}

      iex> AwsSdk.Params.maybe_put(%{}, "Enabled", nil)
      %{}
  """
  @spec maybe_put(map, term, term) :: map
  def maybe_put(map, _key, nil), do: map
  def maybe_put(map, key, value), do: Map.put(map, key, value)

  @doc """
  Maps `""` to `nil`, passing everything else through.

  SweetXml's optional-string modifier (`os`) returns `""` for an absent node
  rather than `nil`, which would otherwise surface as an empty string in a
  response map.

      iex> AwsSdk.Params.nilify("")
      nil

      iex> AwsSdk.Params.nilify("us-east-1")
      "us-east-1"
  """
  @spec nilify(term) :: term
  def nilify(""), do: nil
  def nilify(other), do: other
end
```

```elixir
# lib/aws_sdk/body.ex
defmodule AwsSdk.Body do
  @moduledoc """
  Request- and response-body codecs shared by every service.

  Which of these a service uses is fixed by AWS's wire protocol for that
  service, not by this library.
  """

  # AWS owns the response-body namespace and adds new fields over time.
  # `Serializer.deserialize/2` defaults to `to_existing_atom: true, strict: true`,
  # which crashes on any field whose snake-cased atom has not been referenced
  # elsewhere in the project. Bodies must round-trip without crashing, so atom
  # safety is relaxed here. Callers can still override -- their keys win the merge.
  @deserialize_defaults [to_existing_atom: false, strict: false]

  @doc """
  Encodes a JSON request body.

  An empty map encodes as `"{}"` rather than an empty body, which the JSON 1.1
  services require.
  """
  @spec encode_json(map) :: binary
  def encode_json(data) when map_size(data) === 0, do: "{}"
  def encode_json(data), do: data |> :json.encode() |> IO.iodata_to_binary()

  @doc """
  Decodes a JSON response body.

  An empty body decodes to `%{}`. A body that is not JSON is returned unchanged
  rather than raising, so an unexpected error page reaches the caller intact.
  """
  @spec decode_json(binary) :: map | binary
  def decode_json(""), do: %{}

  def decode_json(binary) when is_binary(binary) do
    :json.decode(binary)
  rescue
    _ -> binary
  end

  @doc """
  Encodes a Query-protocol request body, merging in `Action` and `Version`.
  """
  @spec encode_form(map, binary, binary) :: binary
  def encode_form(params, action, api_version) do
    params
    |> Map.merge(%{"Action" => action, "Version" => api_version})
    |> URI.encode_query()
  end

  @doc """
  Merges caller options over the relaxed atom-safety defaults.
  """
  @spec deserialize_opts(keyword) :: keyword
  def deserialize_opts(opts), do: Keyword.merge(@deserialize_defaults, opts)
end
```

### Task 2: `AwsSdk.Endpoint` and `AwsSdk.Config.sandbox_enabled?/1`

`%AwsSdk.Endpoint{}` is the per-service wire configuration that generated modules
emit as a module attribute and hand to a protocol module. It is a **runtime**
struct in `lib/`, not a codegen struct, so generated code carries no dependency
on `AwsSdk.Codegen.*` — which matters because `priv/specs` and the codegen
modules are dev-time only.

This is a deliberate deviation from the spec, which named it
`%AwsSdk.Codegen.Endpoint{}`. One struct serves both the spec files and the
generated modules rather than two structs with identical fields.

**Files:**
- Create: `lib/aws_sdk/endpoint.ex`
- Modify: `lib/aws_sdk/config.ex`
- Test: `test/aws_sdk/endpoint_test.exs`

**Interfaces:**
- Consumes: nothing
- Produces:

```elixir
# lib/aws_sdk/endpoint.ex
defmodule AwsSdk.Endpoint do
  @moduledoc """
  Per-service wire configuration: where a request goes and how it is framed.

  One struct describes both regional and global services. `:region` carries the
  distinction — `nil` means the caller's configured region fills both the host
  template and the SigV4 scope, and a binary pins both regardless of what the
  caller configured.

  Pinning matters: AWS Organizations and IAM resolve at a single endpoint per
  partition, and interpolating a caller-supplied region into their host produces
  a name that does not resolve. Because a pinned `:region` is the only value
  that can reach `host/2`, that failure is unrepresentable rather than guarded
  against per service.

  ## Examples

      # regional
      %AwsSdk.Endpoint{
        signing_name: "autoscaling",
        api_version: "2011-01-01",
        content_type: "application/x-www-form-urlencoded",
        host: "autoscaling.{region}.amazonaws.com",
        region: nil,
        default_region: "us-east-1",
        override_key: :auto_scaling
      }

      # global
      %AwsSdk.Endpoint{
        signing_name: "iam",
        api_version: "2010-05-08",
        content_type: "application/x-www-form-urlencoded",
        host: "iam.amazonaws.com",
        region: "us-east-1",
        default_region: "us-east-1",
        override_key: :iam
      }
  """

  @enforce_keys [:signing_name, :api_version, :content_type, :host, :default_region, :override_key]
  defstruct [
    :signing_name,
    :api_version,
    :content_type,
    :target_prefix,
    :host,
    :region,
    :default_region,
    :override_key
  ]

  @type t :: %__MODULE__{
          signing_name: String.t(),
          api_version: String.t(),
          content_type: String.t(),
          target_prefix: String.t() | nil,
          host: String.t(),
          region: String.t() | nil,
          default_region: String.t(),
          override_key: atom
        }

  @doc """
  Returns the region to use for both the host and the SigV4 scope.

  A pinned `:region` wins over anything the caller supplied.
  """
  @spec resolve_region(t, keyword) :: String.t()
  def resolve_region(%__MODULE__{region: region}, _opts) when is_binary(region), do: region

  def resolve_region(%__MODULE__{default_region: default}, opts),
    do: opts[:region] || AwsSdk.Config.region() || default

  @doc """
  Interpolates `region` into the host template.

  A host with no `{region}` placeholder is returned unchanged.
  """
  @spec host(t, String.t()) :: String.t()
  def host(%__MODULE__{host: host}, region), do: String.replace(host, "{region}", region)
end
```

```elixir
# lib/aws_sdk/protocol/query.ex
defmodule AwsSdk.Protocol.Query do
  @moduledoc """
  Builds an `AwsSdk.Operation` for AWS's Query protocol.

  Form-urlencoded request, XML response, `Action` and `Version` carried in the
  body. Used by IAM, STS, Auto Scaling and ELBv2 — this is AWS's protocol choice
  per service (botocore `"protocol": "query"`), not a decision this library
  makes.
  """

  alias AwsSdk.{Body, Client, Endpoint, Operation}

  @doc """
  Builds a signed-ready operation for `action` with `params`.

  Returns `{:error, term}` if credentials or region cannot be resolved.
  """
  @spec build(String.t(), map, Endpoint.t(), keyword) ::
          {:ok, Operation.t()} | {:error, term}
  def build(action, params, %Endpoint{} = endpoint, opts) do
    region = Endpoint.resolve_region(endpoint, opts)
    opts = Keyword.put(opts, :region, region)

    with {:ok, config} <-
           Client.resolve_config(endpoint.override_key, opts, &Endpoint.host(endpoint, &1)) do
      op = %Operation{
        method: :post,
        url: Client.simple_url(config),
        headers: [{"content-type", endpoint.content_type}],
        body: Body.encode_form(params, action, endpoint.api_version),
        service: endpoint.signing_name,
        region: config.region,
        access_key_id: config.access_key_id,
        secret_access_key: config.secret_access_key,
        security_token: config.security_token,
        http: Keyword.get(opts, :http, [])
      }

      {:ok, Client.apply_overrides(op, opts[endpoint.override_key] || [])}
    end
  end
end
```

```elixir
  @doc """
  Replaces whole fields on a built operation from per-service opts.

  Only `#{inspect(@override_keys)}` are honoured. `:scheme`, `:host` and `:port`
  are not overrides in this sense — `resolve_config/3` consumes those before the
  URL is composed.

      AwsSdk.Client.apply_overrides(op, url: "http://localhost:4566/")
  """
  @spec apply_overrides(AwsSdk.Operation.t(), keyword) :: AwsSdk.Operation.t()
  def apply_overrides(op, overrides) do
    Enum.reduce(@override_keys, op, fn key, acc ->
      case Keyword.fetch(overrides, key) do
        {:ok, value} -> Map.put(acc, key, value)
        :error -> acc
      end
    end)
  end
```

```elixir
# lib/mix/tasks/aws_sdk.models.refresh.ex
defmodule Mix.Tasks.AwsSdk.Models.Refresh do
  @shortdoc "Re-pulls the vendored AWS SDK Go v2 service models"

  @moduledoc """
  Downloads the Smithy service models that `mix aws_sdk.gen` reads.

      mix aws_sdk.models.refresh          # every service in @services
      mix aws_sdk.models.refresh ec2      # one service

  Models are committed to git. Refreshing them can change generated code across
  services at once, so review the diff and run `mix aws_sdk.gen --check` after.
  """

  use Mix.Task

  @base "https://raw.githubusercontent.com/aws/aws-sdk-go-v2/main/codegen/sdk-codegen/aws-models"

  # local name => upstream model filename
  @services %{
    "autoscaling" => "auto-scaling.json"
  }

  @impl Mix.Task
  def run(args) do
    Mix.Task.run("app.start")

    services =
      case args do
        [] -> @services
        names -> Map.take(@services, names)
      end

    if services == %{}, do: Mix.raise("no known service in #{inspect(args)}")

    Enum.each(services, fn {local, remote} ->
      path = Path.join("models", "#{local}.json")
      Mix.shell().info("fetching #{remote} -> #{path}")

      case System.cmd("curl", ["-fsSL", "-o", path, "#{@base}/#{remote}"]) do
        {_, 0} -> :ok
        {out, code} -> Mix.raise("curl failed (#{code}) for #{remote}: #{out}")
      end
    end)
  end
end
```

```elixir
# lib/aws_sdk/codegen/field.ex
defmodule AwsSdk.Codegen.Field do
  @moduledoc """
  One member of an AWS request or response structure.

  The same struct drives both directions: the response compiler turns a field
  list into SweetXml selectors, and the request compiler turns one into an XML
  document.

  `type`, `cardinality` and `optional` together determine the emitted selector
  with no remaining special cases:

      :string,    :one,  optional: false -> ~x"./Wire/text()"s
      :string,    :one,  optional: true  -> ~x"./Wire/text()"os, then nilify/1
      :integer,   :one,  optional: true  -> ~x"./Wire/text()"oi
      :string,    :many, _               -> ~x"./Wire/text()"sl
      :structure, :one,  optional: true  -> [~x"./Wire"o, ...]
      :structure, :many, _               -> [~x"./Wire"l, ...]

  `fields` is non-empty only when `type` is `:structure`, and is an ordered list
  rather than a map so generated output is deterministic across runs.

  `:boolean` and `:datetime` have no SweetXml modifier. They extract as `os` and
  are converted by a generated coercion pass.
  """

  @enforce_keys [:name, :wire, :type]
  defstruct [:name, :wire, :type, cardinality: :one, optional: false, fields: []]

  @type type :: :string | :integer | :boolean | :datetime | :json | :structure

  @type t :: %__MODULE__{
          name: atom,
          wire: String.t(),
          type: type,
          cardinality: :one | :many,
          optional: boolean,
          fields: [t]
        }
end
```

#### What we take from aws-codegen

Nothing executable. No dependency is added, no code is vendored, nothing is
copied. `aws-beam/aws-codegen` is a **peer project** — another generator reading
the same AWS models and emitting a different code style. We cannot use its
backend to produce our output.

What it gives us is documentation. AWS's Smithy JSON AST has no published schema,
and `aws-codegen` is a working reader of it. Three facts below are ones you would
otherwise have to reverse-engineer from the JSON. Read them, then write
`AwsSdk.Codegen.Model` from scratch.

All references are pinned to commit `06b1a3d0438be2d3490d7de3c0860da0ddbc6381`:
<https://github.com/aws-beam/aws-codegen/blob/06b1a3d0438be2d3490d7de3c0860da0ddbc6381/lib/aws_codegen/spec.ex>

**Fact 1 — how to find the service shape** (`spec.ex:80-84`):

```elixir
  def find_service(api) do
    Enum.find_value(api["shapes"], fn {service, value} ->
      if match?(%{"type" => "service"}, value), do: service
    end)
  end
```

A Smithy model is a flat `"shapes"` map keyed by fully-qualified id
(`"com.amazonaws.autoscaling#AutoScaling"`). Exactly one shape has
`"type" => "service"`, and its key is the namespace prefix for every other shape
in the file. Take this as-is — `AwsSdk.Codegen.Model` needs the same lookup.

**Fact 2 — where the protocol lives** (`spec.ex:37-64`):

```elixir
    traits = api["shapes"]["com.amazonaws." <> api_name <> "#" <> service_name]["traits"]
    protocol0 =
      Enum.find_value(traits, fn {k, _v} ->
        case String.split(k, "#") do
          ["aws.protocols", protocol] -> protocol
          _ ->
            nil
        end
      end)
```

```elixir
      protocol =
        protocol0
        |> String.replace("restJson1", "rest_json")
        |> String.replace(["awsJson1_0", "awsJson1_1"], "json")
        |> String.replace("awsQuery", "query")
        |> String.replace("restXml", "rest_xml")
        |> String.replace("ec2Query", "ec2")
        |> then(fn value ->
          if value in ~w(rest_json json query rest_xml ec2) do
            value
          else
            raise "the protocol #{value} is not valid"
          end
        end)
        |> String.to_atom()
```

This is the fact worth the most: the protocol is not a field, it is the *presence
of a trait* on the service shape whose key is namespaced `aws.protocols#`. So
`"aws.protocols#awsQuery" => %{}` is how a model says "Query protocol". You would
not guess that from reading the JSON. The trait-name → protocol mapping is the
authoritative list, and raising on an unknown value rather than defaulting is the
right behaviour — copy that decision.

**Fact 3 — where the service's display name lives** (`spec.ex:99-101`):

```elixir
  defp module_name(traits, language) do
    service_name =
      traits["aws.api#service"]["sdkId"]
```

The `aws.api#service` trait carries `sdkId` (and `arnNamespace`). We do not use
`sdkId` for module naming — `%AwsSdk.Codegen.Service{module:}` is curation, typed
by hand in the spec file. It is useful in `mix aws_sdk.scaffold` output as a
comment, and as the check that you loaded the model you meant to.

#### Where we deviate, and why

| aws-codegen | `AwsSdk.Codegen.Model` | Why |
|---|---|---|
| `awsJson1_0` and `awsJson1_1` both map to `:json` (`spec.ex:53`) | `:json_1_0` and `:json_1_1` stay distinct | They differ on the wire: the `content-type` is `application/x-amz-json-1.0` versus `-1.1`. Collapsing them is safe for aws-codegen because its template emits the version separately; it is not safe for us. |

- [ ] **Step 3: Implement `AwsSdk.Codegen.Model`**

This is the largest single piece of the plan and the one where the model format
found in Task 6 Step 1 governs. Write it against the actual JSON, not against an
assumed schema. The required behaviours, each pinned by a test above:

- `load/1` reads `models/<basename>.json` and `:json.decode`s it. Cache nothing;
  generation is a one-shot task.
- Resolve a Smithy shape reference (`{"target" => "com.amazonaws.autoscaling#Foo"}`)
  to its shape map.
- `response/2` finds the operation shape, takes its `output` target, drops the
  `<XxxResponse>`/`<XxxResult>` envelope to produce `root`, and maps every member
  to a `%AwsSdk.Codegen.Field{}`.
- Member name → `name` is `Recase.to_snake/1` on the member key, then
  `String.to_atom/1`. `wire` is the member's `smithy.api#xmlName` trait if
  present, else the member key.
- Smithy type → `%AwsSdk.Codegen.Field{}` `type`:
  `string`/`enum` → `:string`; `integer`/`long`/`short` → `:integer`;
  `boolean` → `:boolean`; `timestamp` → `:datetime`; `structure`/`union` → `:structure`;
  `document` → `:json`.
- A `list` shape sets `cardinality: :many` and the field takes the *member*
  shape's type. For a non-flattened list the wire path gains `/member` — hence
  `"InstanceRefreshes/member"`. A list carrying `smithy.api#xmlFlattened` does
  not.
- `optional: true` unless the member carries `smithy.api#required`.
- Recursion must terminate. AWS models contain recursive shapes; carry a `seen`
  MapSet of shape ids down the walk and stop at a repeat, emitting no children.
  Add a test for this if the AutoScaling model has such a shape.
- `request/2` for a `query`-protocol service is a constant. Read the protocol from
  the service shape's traits per Fact 2 above and raise on an unrecognised one
  rather than defaulting — a silent wrong default would generate wrong wire code.
  The mapping, keeping the two JSON versions distinct as the deviation table
  requires:

```elixir
  @protocols %{
    "awsQuery" => :query,
    "ec2Query" => :ec2,
    "awsJson1_0" => :json_1_0,
    "awsJson1_1" => :json_1_1,
    "restJson1" => :rest_json,
    "restXml" => :rest_xml
  }
```

  Only `:query`, `:ec2`, `:json_1_1` and `:rest_xml` have a protocol module after
  Task 5. A spec naming a service whose model declares `:json_1_0` or

```elixir
# lib/aws_sdk/codegen/coerce.ex
defmodule AwsSdk.Codegen.Coerce do
  @moduledoc """
  Leaf-value coercions applied to extracted XML values.

  SweetXml has no boolean or timestamp modifier, so members the AWS model types
  as `boolean` or `timestamp` are extracted as optional strings and converted
  here. Coercion changes values, not shape, which is what the response fidelity
  rules in `CLAUDE.md` require.

  Every function maps `""` and `nil` to `nil`, and passes an unparseable value
  through unchanged rather than raising — a response that AWS changed the type of
  should reach the caller, not crash the client.
  """

  @doc """
      iex> AwsSdk.Codegen.Coerce.boolean("true")
      true

      iex> AwsSdk.Codegen.Coerce.boolean("")
      nil

      iex> AwsSdk.Codegen.Coerce.boolean("yes")
      "yes"
  """
  @spec boolean(term) :: boolean | nil | term
  def boolean(""), do: nil
  def boolean(nil), do: nil
  def boolean("true"), do: true
  def boolean("false"), do: false
  def boolean(other), do: other

  @doc """
      iex> AwsSdk.Codegen.Coerce.datetime("2026-01-01T00:00:00Z")
      ~U[2026-01-01 00:00:00Z]

      iex> AwsSdk.Codegen.Coerce.datetime("")
      nil
  """
  @spec datetime(term) :: DateTime.t() | nil | term
  def datetime(""), do: nil
  def datetime(nil), do: nil

  def datetime(binary) when is_binary(binary) do
    case DateTime.from_iso8601(binary) do
      {:ok, datetime, _offset} -> datetime
      {:error, _reason} -> binary
    end
  end

  def datetime(other), do: other

  @doc """
      iex> AwsSdk.Codegen.Coerce.json(~s({"a":1}))
      %{"a" => 1}

      iex> AwsSdk.Codegen.Coerce.json("")
      nil
  """
  @spec json(term) :: map | nil | term
  def json(""), do: nil
  def json(nil), do: nil

  def json(binary) when is_binary(binary) do
    :json.decode(binary)
  rescue
    _ -> binary
  end

  def json(other), do: other
end
```

The example block is rendered by walking `response.fields` and building a map
literal, filling each leaf from the field's `example` if the spec set one, else a
type default:

| type | default example |
|---|---|

| scalar, `:many` | `[]` |

Render the map with `inspect(term, pretty: true, limit: :infinity, width: 60)`,
then prefix every line with `#=> ` and indent to match the surrounding heredoc.

The point of rendering from `response.fields` rather than from a hand-typed
